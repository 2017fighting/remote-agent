# prompt 与镜像解耦

prompt 模板放在 home-ops 的 ConfigMap 里；Job 通过 `AGENT_ROLE` 声明角色，runner 读挂载路径、把同名模板渲染成 durable 的 prompt section（[ADR-0008](0008-durable-runtime-base.md)）。ConfigMap `remote-agent-prompts` 的键不是「一个 role 一份」那么平：`_common`（所有 role 拼在最前：不写/不做清单、commit 先于 review、收尾 review、自述、seam）＋ `implement-ticket` / `implement-spec`（各自的差异）＋ `review-standards` / `review-spec`（reviewer conversation 的两轴系统提示）。共享骨架只省重复，渲染出来的 prompt 仍然自包含（[清单](https://github.com/2017fighting/remote-agent/blob/main/docs/agents/prompt-checklist.md)）。镜像里只有 runner、durable、工具链这类公共物，不含任何 prompt，**也没有 skill 层**：v1 不实现 skill 加载（durable 没有 Skill 工具、没有 slash command，规范里的 `Skills`/`renderSkills` 只是未实现草图），mattpocock 那套里 AFK 必需的语义直接写进 prompt 模板。这样镜像能继续被别的角色（explore、review）复用，改 prompt 也不必重建镜像。代价是 prompt 与 App 代码之间的契约（角色名、结果格式、环境变量）分处两个仓库，容易漂移；且模板要自包含，原来靠 skill 提供的细节得一条条搬进去。
